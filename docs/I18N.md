# Internationalization

The active app shell uses NSH's built-in `nsh/i18n`. Translations live in
`locales/en.json` and `locales/zh.json`, beside `nsh.json`; NSH bundles them
automatically. The Chinese catalog currently contains Simplified Chinese. Its
base `zh` tag also matches system tags such as `zh-CN` and `zh-Hans-CN`.

The Preferences page offers Follow system, 简体中文 and English. Changes are
applied on Save & apply, including tooltips and accessibility labels. Follow
system uses the first supported preferred language, with English as the fallback.
Explicit choices are saved by NSH's native `Storage` under `ferrix.language`.
Following the system again removes that preference. An unsupported stored value
is ignored.

`src/app.tsx` creates the language settings at startup, independently of the title
bar and Preferences page, so the saved language is restored before opening
Preferences. The title bar has no language selector.

Call `t("navigation.keys")` from `src/i18n.ts` inside a reactive text or prop
binding. Do not translate into module-level constants: they will keep their
original language. Keep navigation IDs, Redis keys, commands and user data
independent of translated display strings. Add the same key to both catalogs;
interpolation uses `%{name}` and `t("key", { name })`.

The currently mounted shell and pages (`src/app.tsx`, `src/components/`,
`src/pages/`) are localized.
The previous demo workspace under `ui/` is not mounted by the entry point.

Run `nsh test tests/i18n.test.tsx --filter i18n` for language matching, runtime
switching, storage restoration, system reset and translated accessibility labels.
